SLA Escrow

Uptime credits decided by independent validators GenLayer Bradbury · chain 4221

An uptime guarantee that pays out by itself.

Today an SLA credit means filing a ticket and waiting for the provider to agree it was down, judged by a status page the provider writes. Here the provider bonds GEN in a GenLayer Intelligent Contract written in Rust. When the customer reports an outage, the leader and every validator probe the endpoint from their own network. The credit is paid only if they agree it is down.

Offer an SLA (provider)

Validators probe the endpoint when you create the SLA. It can only start on an endpoint that is up.

How it works

  1. Bond. The provider names the endpoint, the check, the customer and the credit per outage, and locks a bond. Validators confirm the endpoint is up before the SLA starts.
  2. Report. When the customer's monitoring sees an outage, the customer presses Report (or a bot sends the same call).
  3. Probe. The leader and each validator probe the endpoint themselves. An HTTP check is down on errors, timeouts or status ≥ 400; an EVM RPC check is also down when its head block is older than the limit.
  4. Credit. If they agree it is down, the credit goes to the customer from the bond. One credit per cooldown window.
  5. End. After the term, or when the customer releases early, the provider withdraws what is left of the bond.

No self-reported status

The provider's status page plays no part. Each validator measures from its own network, so a regional blip seen by one node does not pay out.

Benefit of the doubt

If the endpoint flaps and validators disagree, the transaction does not reach consensus and nothing is paid. Only clear outages cost the provider.

Money only moves by rule

Credits go only to the customer, the remaining bond only to the provider, and each party triggers its own transfer.

Check before you send

“Check now” asks one node to run the probe without a transaction, so the customer sees the likely verdict before paying any fee.
